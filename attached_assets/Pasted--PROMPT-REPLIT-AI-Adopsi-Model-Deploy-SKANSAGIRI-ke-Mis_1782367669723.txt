## MASTER CONTEXT — BACA SEBELUM APAPUN

Kamu adalah engineer yang sedang mengerjakan proyek **MisiPintar**, sebuah aplikasi Next.js 16 (App Router, TypeScript) untuk manajemen keuangan keluarga berbasis gamifikasi. App ini di-host di **cPanel shared hosting** menggunakan **Phusion Passenger** sebagai Node.js runner.

Kamu sudah punya referensi proyek lain bernama **SKANSAGIRI** yang model deploy-nya lebih matang dan robust. Tugas kamu adalah **mengadopsi pola deploy SKANSAGIRI ke MisiPintar** — bukan migrasi framework, melainkan peningkatan infrastruktur deploy saja.

## BAGIAN 1 — KONTEKS TEKNIS YANG WAJIB DIPAHAMI

### 1.1 Stack MisiPintar (TIDAK BERUBAH)
- **Framework**: Next.js 16.2.9 dengan App Router
- **Runtime backend**: Next.js standalone (`output: "standalone"` di `next.config.ts`)
- **Database**: PostgreSQL via Prisma v7 + `@prisma/adapter-pg`
- **Auth**: NextAuth v5 beta
- **Build tool dev**: Turbopack (default Next.js 16, `npm run dev`)
- **Build tool cPanel**: WAJIB `--webpack` (lihat 1.3)
- **Entry point Passenger**: `app.js` (CJS, bukan ESM)
- **Port**: 5000

### 1.2 Constraint cPanel Shared Hosting
- Passenger menjalankan `app.js` sebagai entry point
- `node_modules` bisa jadi symlink ke `~/nodevenv/` — ini masalah untuk Turbopack
- `ulimit -u` rendah → thread harus dibatasi: `RAYON_NUM_THREADS=1`, `TOKIO_WORKER_THREADS=1`, `UV_THREADPOOL_SIZE=1`
- RAM build dibatasi: `NODE_OPTIONS=--max-old-space-size=1024`
- Restart Passenger: `touch tmp/restart.txt` (TIDAK perlu SSH/UI cPanel)

### 1.3 Kenapa WAJIB `next build --webpack` di cPanel (JANGAN DIUBAH)
Turbopack panic di cPanel karena `node_modules` adalah symlink ke `~/nodevenv/` di luar project root:
```
Error: Symlink [project]/node_modules is invalid, it points out of the filesystem root
```
Webpack mengikuti symlink via resolusi Node.js standar → tidak panic.
**JANGAN tambahkan `.babelrc`** — akan men-disable SWC dan merusak Server Actions.

### 1.4 npm cPanel: Harus Pakai Sistem npm (Bukan Wrapper)
cPanel membungkus `npm` dengan wrapper yang menginstall paket ke `~/nodevenv/` bukan ke `./node_modules/` lokal. Harus deteksi dan pakai npm sistem:
```bash
NODE_MAJOR=$(node --version | grep -oP '^\d+')
SYSTEM_NPM="/opt/cpanel/ea-nodejs${NODE_MAJOR}/bin/npm"
```
Jika tidak ditemukan, fallback ke `env -u npm_config_prefix -u NPM_CONFIG_PREFIX npm`.

### 1.5 Paket yang WAJIB di `serverExternalPackages` (next.config.ts)
Satu sumber kebenaran — dipakai `serverExternalPackages` (Turbopack) DAN `webpack.externals` (build cPanel):
```typescript
const SERVER_EXTERNAL_PACKAGES = [
  "nodemailer",          // CJS-heavy
  "bullmq",              // CJS + dynamic require
  "@prisma/client",      // native .node binary
  "prisma",              // native .node binary
  "@react-pdf/renderer", // ESM-only (type:"module")
  "nanoid",              // ESM-only (type:"module", v5+)
] as const;
```

### 1.6 Prisma v7 — Quirk CLI
Prisma v7 menghapus `url` dari `schema.prisma`. Untuk CLI:
```bash
./node_modules/.bin/prisma migrate deploy
# url diambil dari DATABASE_URL env var yang sudah di-source dari .env
```
Bukan `--url` flag — cukup pastikan `DATABASE_URL` sudah ada di environment sebelum perintah dijalankan.

### 1.7 Output Build Next.js Standalone
Setelah `next build --webpack`, output penting ada di:
```
.next/
  standalone/
    server.js      ← entry point yang dijalankan oleh app.js
    node_modules/  ← subset dependensi
  static/          ← perlu dicopy ke .next/standalone/.next/static/
public/            ← perlu dicopy ke .next/standalone/public/
```
Kedua copy ini WAJIB dilakukan setelah build atau static assets tidak akan tersaji.

## BAGIAN 2 — MODEL DEPLOY SKANSAGIRI (REFERENSI UNTUK DIADOPSI)

SKANSAGIRI adalah proyek berbeda (Vite + Express + flat-file JSON) tapi pola deploy-nya lebih matang. Yang diadopsi **hanya pola/filosofinya**, bukan teknologinya.

### 2.1 Filosofi 8-Langkah SKANSAGIRI
```
[1] Validasi prasyarat (.env, DATABASE_URL, git tersedia)
[2] Backup file-file terlindungi sebelum git pull
[3] git fetch + reset --hard origin/<branch>   ← pull bersih, tidak ada konflik merge
[4] Restore file-file terlindungi (overwrite-proof dari git)
[5] Deteksi npm sistem cPanel
[6] npm install ke ./node_modules lokal
[7] Build + verifikasi output + rollback otomatis jika gagal
[8] touch tmp/restart.txt → Passenger restart tanpa UI cPanel
```

### 2.2 Fitur Unggulan SKANSAGIRI yang Harus Diadopsi

**A. Backup & Restore File Terlindungi**
```bash
PROTECT_DIR="$APP_DIR/.deploy_protect_$$"
backup_protected() {
  mkdir -p "$PROTECT_DIR"
  for item in "${PROTECTED_FILES[@]}"; do
    [ -e "$APP_DIR/$item" ] && cp -r "$APP_DIR/$item" "$PROTECT_DIR/$item"
  done
}
restore_protected() {
  for item in "${PROTECTED_FILES[@]}"; do
    local bak="$PROTECT_DIR/$item"
    if [ -e "$bak" ]; then
      rm -rf "$APP_DIR/$item"
      cp -r "$bak" "$APP_DIR/$item"
    fi
  done
}
```

**B. Rollback Build Otomatis**
```bash
DIST_BACKUP="$APP_DIR/.next_backup_$$"
backup_dist() {
  [ -d "$APP_DIR/.next/standalone" ] && cp -r "$APP_DIR/.next" "$DIST_BACKUP"
}
rollback_dist() {
  if [ -d "$DIST_BACKUP" ]; then
    rm -rf "$APP_DIR/.next"
    cp -r "$DIST_BACKUP" "$APP_DIR/.next"
  fi
}
```

**C. ERR Trap untuk Auto-Rollback**
```bash
trap 'log_err "Gagal di baris $LINENO"; rollback_dist; restore_protected; cleanup' ERR
trap 'rm -rf "$PROTECT_DIR" "$DIST_BACKUP"' EXIT
```

**D. Logging ke File dengan Rotation**
```bash
LOG_FILE="$APP_DIR/deploy.log"
MAX_LOG_LINES=2000
_log() {
  local ts="$(date '+%Y-%m-%d %H:%M:%S')" lv="$1" col="$2" msg="$3"
  printf "${CC}[%s]${CX} ${CB}%s${CX} ${col}%s${CX}\n" "$ts" "[$lv]" "$msg"
  printf "[%s] [%s] %s\n" "$ts" "$lv" "$msg" >> "$LOG_FILE"
}
```

**E. Verifikasi Post-Build**
Cek file wajib ada, ukuran masuk akal, baru lanjut ke restart.

**F. `app.js` dengan Logging + Error Capture Dini**
Log ke `logs/app.log` dengan rotation 512KB, tangkap `uncaughtException` dan `unhandledRejection` sebelum server dimuat.

**Fungsi logging dengan dual output (stdout + file):**
```bash
_log() {
  local ts="$(date '+%Y-%m-%d %H:%M:%S')" lv="$1" col="$2" msg="$3"
  printf "${CC}[%s]${CX} ${CB}%s${CX} ${col}%s${CX}\n" "$ts" "[$lv]" "$msg"
  printf "[%s] [%s] %s\n" "$ts" "$lv" "$msg" >> "$LOG_FILE"
}
log_ok()   { _log " OK " "$CG" "$1"; }
log_info() { _log "INFO" ""   "$1"; }
log_warn() { _log "WARN" "$CY" "$1"; }
log_err()  { _log " ERR" "$CR" "$1"; }
rotate_log() {
  [ -f "$LOG_FILE" ] && [ "$(wc -l < "$LOG_FILE")" -gt "$MAX_LOG_LINES" ] && \
    tail -n "$MAX_LOG_LINES" "$LOG_FILE" > "${LOG_FILE}.tmp" && \
    mv "${LOG_FILE}.tmp" "$LOG_FILE" || true
}
```

**Backup/restore helpers (sama persis dengan model SKANSAGIRI, adaptasi untuk MisiPintar):**
- `backup_protected()` — backup `.env` dan `app.js` ke `$APP_DIR/.deploy_protect_$$`
- `restore_protected()` — restore dari backup
- `backup_dist()` — backup `.next/` lama ke `.next_backup_$$`
- `rollback_dist()` — restore `.next/` dari backup
- `cleanup()` — `rm -rf "$PROTECT_DIR" "$DIST_BACKUP"` — dipanggil oleh EXIT trap

**Trap:**
```bash

trap 'cleanup' EXIT
```

### TUGAS 3.2 — Update `app.js` (TAMBAHKAN logging, PERTAHANKAN struktur CJS)

`app.js` saat ini hanya `require(standaloneServer)` tanpa logging. Update dengan menambahkan:

**Logging ke file dengan rotation (diadopsi dari SKANSAGIRI):**
```javascript
"use strict";

const path = require("path");
const fs   = require("fs");

// ── Logger dengan rotation ─────────────────────────────────────────────────
const LOG_DIR  = path.join(__dirname, "logs");
const LOG_FILE = path.join(LOG_DIR, "app.log");
const LOG_OLD  = path.join(LOG_DIR, "app.log.1");
const MAX_BYTES = 512 * 1024; // rotate setiap 512 KB

function writeLog(level, message) {
  const line = `${new Date().toISOString()} [${level}] ${message}\n`;
  (level === "ERROR" ? process.stderr : process.stdout).write(line);
  try {
    if (!fs.existsSync(LOG_DIR)) fs.mkdirSync(LOG_DIR, { recursive: true });
    if (fs.existsSync(LOG_FILE) && fs.statSync(LOG_FILE).size > MAX_BYTES) {
      if (fs.existsSync(LOG_OLD)) {
        try { fs.renameSync(LOG_OLD, path.join(LOG_DIR, "app.log.2")); } catch {}
      }
      fs.renameSync(LOG_FILE, LOG_OLD);
    }
    fs.appendFileSync(LOG_FILE, line, "utf-8");
  } catch (e) {
    process.stderr.write(`[LOG-WRITE-FAIL] ${e.message}\n`);
  }
}
```

**Error capture dini (SEBELUM require apapun):**
```javascript
process.on("uncaughtException", (err) => {
  writeLog("ERROR", `Uncaught exception: ${err.stack || err.message}`);
  process.exit(1);
});
process.on("unhandledRejection", (reason) => {
  writeLog("ERROR", `Unhandled rejection: ${reason instanceof Error ? reason.stack : String(reason)}`);
  process.exit(1);
});
```

**Load .env dan log startup:**
```javascript
require("dotenv").config({ path: path.join(__dirname, ".env") });

writeLog("INFO", `Starting — NODE_ENV=${process.env.NODE_ENV || "production"}  Node=${process.version}  PID=${process.pid}`);
```

**Load standalone server dengan error handling:**
```javascript
const standaloneServer = path.join(__dirname, ".next", "standalone", "server.js");

if (!fs.existsSync(standaloneServer)) {
  writeLog("ERROR", `Build belum tersedia. Jalankan: bash deploy.sh`);
  writeLog("ERROR", `Path: ${standaloneServer}`);
  process.exit(1);
}

try {
  require(standaloneServer);
  writeLog("INFO", ".next/standalone/server.js loaded — Next.js server starting");
} catch (err) {
  writeLog("ERROR", `Gagal load standalone server:\n${err.stack || err.message}`);
  process.exit(1);
}
```

**PENTING:** `app.js` harus tetap CJS (`"use strict"`, `require`, `module.exports`). MisiPintar TIDAK punya `"type": "module"` di `package.json`. Berbeda dengan SKANSAGIRI yang ESM.
