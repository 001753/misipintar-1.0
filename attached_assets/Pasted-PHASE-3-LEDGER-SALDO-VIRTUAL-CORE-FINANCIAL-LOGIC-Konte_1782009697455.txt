PHASE 3 — LEDGER & SALDO VIRTUAL (CORE FINANCIAL LOGIC)

Konteks: Membangun semua logika finansial virtual — transfer, tabungan, interest engine.
ZERO client-side math. Semua di server. Semua atomik.

TUGAS [3.1] — SERVER ACTION: TRANSFER SALDO
Buat di `src/actions/ledger.ts`:

transferToSavings(childId, amount):
- Ambil familySpaceId dari session (PARENT atau CHILD yang bersangkutan)
- Validasi kepemilikan
- WAJIB prisma.$transaction():
  1. Baca Child saat ini (lock for update jika PostgreSQL mendukung)
  2. Validasi: amount > 0 DAN child.balance >= amount → jika tidak, THROW error tanpa ubah apapun
  3. Update Child: balance -= amount, savingsBalance += amount
  4. Buat 2 baris TransactionLedger:
     - Baris 1: type SAVINGS_DEPOSIT, amount positif di savingsBalance
     - Baris 2: type ADJUSTMENT (pengurangan dari balance utama), amount negatif
  5. Buat Notification
- Return { success, newBalance, newSavingsBalance } atau { error: "INSUFFICIENT_BALANCE" }

transferToCharity(childId, amount):
- Sama dengan transferToSavings tapi ke charityBalance
- type: CHARITY

withdrawFromSavings(childId, amount):
- Validasi child.savingsBalance >= amount
- Atomik: savingsBalance -= amount, balance += amount
- Ledger: type SAVINGS_WITHDRAW

TUGAS [3.2] — INTEREST ENGINE (CRON JOB)
Buat `src/lib/queue/workers/interest.worker.ts`:

Logika:
- Berjalan setiap hari (BullMQ repeatable job, cron: "0 0 * * *")
- Distributed lock via Redis: key = "cron:mutex:interest", TTL = 5 menit
  - Jika lock ada → skip (sudah berjalan di instance lain)
  - Jika tidak ada → ambil lock, jalankan, release setelah selesai
- Proses dalam batch 500 user:
  1. Ambil semua Child yang familySpace.subscription.plan.limits.hasInterest === true
  2. Hitung bunga: savingsBalance * (interestRate / 100) — interestRate dari AppConfig
  3. Jika bunga > 0: update savingsBalance, buat TransactionLedger type INTEREST
  4. Lanjut batch berikutnya
- Log hasil ke console DAN tulis summary ke AdminAuditLog

Buat `src/app/api/queue/worker/route.ts` untuk start workers.

TUGAS [3.3] — TAX ENGINE (OPSIONAL per plan)
