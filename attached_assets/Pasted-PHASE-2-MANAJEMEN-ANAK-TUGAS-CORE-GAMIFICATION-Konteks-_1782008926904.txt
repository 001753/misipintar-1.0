PHASE 2 — MANAJEMEN ANAK & TUGAS (CORE GAMIFICATION)

Konteks: Fitur inti gamifikasi — parent mengelola anak, membuat tugas, anak mengklaim tugas.
Semua Server Actions. Semua validasi familySpaceId dari SESSION (bukan dari input user).

TUGAS [2.1] — SERVER ACTION: MANAJEMEN ANAK
Buat/tambahkan ke `src/actions/child.ts`:

createChild(input):
- Input: name, username, password, avatar?
- Ambil familySpaceId dari session (JANGAN dari parameter)
- Validasi: cek limit maxChildren sesuai plan aktif subscription
- Validasi password: min 6 char, tidak boleh sama dengan username
- Hash password dengan bcrypt (saltRounds: 12)
- Cek unique constraint [familySpaceId, username] sebelum insert
- Buat Child dengan balance=0, savingsBalance=0, charityBalance=0
- Return { success, childId } atau { error }

updateChild(childId, input):
- Validasi child.familySpaceId === session.familySpaceId (anti cross-tenant)
- Update name, avatar saja — password update via fungsi terpisah
- Return { success } atau { error }

changeChildPassword(childId, newPassword):
- Validasi kepemilikan (familySpaceId match)
- Validasi: min 6 char, tidak sama username
- Hash dan update — JANGAN simpan plaintext

deleteChild(childId):
- Validasi kepemilikan
- Soft delete: tambahkan field `deletedAt` (jangan hapus ledger history)

TUGAS [2.2] — SERVER ACTION: MANAJEMEN TUGAS
Buat `src/actions/task.ts`:

createTask(input):
- Input: childId, title, description?, rewardAmount
- Ambil familySpaceId dari session
- Validasi child.familySpaceId === session.familySpaceId
- Validasi: cek limit maxTasksPerMonth sesuai plan (hitung task bulan ini)
- Validasi rewardAmount: positif, tidak nol
- Buat Task dengan status PENDING
- Return { success, taskId }

claimTask(taskId, proofPhotoUrl?):
- Dipanggil dari session CHILD
- Ambil childId dari session (BUKAN dari parameter)
- Validasi task.childId === session.childId DAN task.familySpaceId === session.familySpaceId
- Validasi status: hanya PENDING yang bisa diklaim
- Update status → CLAIMED, set claimedAt
- Kirim notifikasi ke parent via FCM + tulis ke tabel Notification
- Return { success }

approveTask(taskId):
- Dipanggil dari session PARENT
- Validasi task.familySpaceId === session.familySpaceId
- Validasi status: hanya CLAIMED yang bisa di-approve
- WAJIB gunakan prisma.$transaction():
  1. Update Task status → APPROVED, set approvedAt
  2. Baca Child.balance saat ini (dalam transaksi yang sama)
  3. Update Child.balance += task.rewardAmount
  4. Buat 1 baris TransactionLedger dengan:
     - type: TASK_REWARD
     - amount: task.rewardAmount
     - balanceBefore: nilai sebelum
     - balanceAfter: nilai setelah
     - refId: taskId
  5. Buat Notification untuk child
- Kirim FCM ke child setelah transaksi berhasil
- Return { success, newBalance }

rejectTask(taskId, reason):
- Validasi kepemilikan (familySpaceId)
- Validasi status: hanya CLAIMED
- Update status → REJECTED, set rejectedAt, rejectedReason
- Kirim notifikasi ke child
- Return { success }
